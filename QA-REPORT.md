# QA веб-каталога EXEED Friends

Дата проверки: 17 ноября 2026. Браузер: Chrome 156.0.8078.79, штатная изоляция браузера включена. Проверялась production-сборка, а не только компоненты в режиме разработки.

**Результат: 45 автоматических проверок пройдены.** 25 браузерных сценариев, 11 unit-проверок каталога и корзины, 1 проверка запуска production-модулей, 4 HTTP-проверки backend и 4 проверки механизма автодеплоя. Снимки компьютера, планшета, телефона, схемы и корзины просмотрены вручную.

## Редизайн

- Один рабочий экран: автомобиль → узел → детали. Убраны рекламные секции, повторяющиеся подсказки, условные изображения товаров и лишняя навигация.
- Схема заменена на ортографический боковой вид: колёса одинакового размера, на одной горизонтали, без перспективного разворота.
- На компьютере доступны схема и список разделов; на телефоне список заменён компактным выбором узла. Зоны на схеме имеют размер 44 × 44 px и не пересекаются даже при ширине 320 px.
- Детали показаны строками: наименование и артикул, наличие, цена, добавление. Доставка, VIN-подбор и подробности вынесены в отдельные окна.

## Исправлено во время QA

1. Пересечение двух зон нажатия на 320 px.
2. Недостаточный контраст счётчика, артикулов, подписи выгрузки, footer и текста корзины.
3. Неполная проверка сохранённой корзины: теперь отбрасываются отрицательные цены и неполные данные, дубликаты объединяются с соблюдением лимита.
4. Риск работы с устаревшим состоянием при серии быстрых добавлений: операции используют актуальную корзину.
5. Потеря страницы, сортировки и наличия при перезагрузке: параметры сохраняются в URL.
6. Некорректный ответ API мог попасть в отображение как неполная деталь: данные валидируются до рендера.
7. Общий изменяемый режим источника мог смешать результаты повторной загрузки: источник теперь закреплён за сессией каталога.
8. Слишком длинный Telegram-черновик для большой корзины: применяется короткий текст и сохранение списка в файл.

## Повторение проверки

```sh
npm ci
npm run build
npm run test:web
npm run test:bundle
npm run test:browser
node --test tests/autodeploy.test.mjs
cd server
npm ci
npm run prisma:generate
npm run test:web
```

Для браузерного прогона используется установленный Chrome/Chromium; при необходимости путь задаётся через `PUPPETEER_EXECUTABLE_PATH`. Скрипт поднимает изолированный HTTP-стенд, использует данные выгрузки, моделирует ответы API и не отправляет сообщения, заказы или платежи. В GitHub Actions эта проверка обязательна до публикации релиза. JSON-отчёты и PNG-снимки сохраняются в артефакте `browser-qa-<SHA>`.

## Границы результата

Реальные iOS/Safari, Firefox, экранные дикторы и нативный Telegram WebView в этот прогон не входили. Боевые заказ и оплата не создавались. Применяемость по VIN и достоверность цены поставщика не подтверждаются схемой: это навигационный каталог, точный подбор требует данных поставщика и проверки менеджером. Большая часть текущей выгрузки не содержит явно указанной марки и остаётся в общем поиске.
