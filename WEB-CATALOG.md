# Веб-каталог EXEED Friends

Обычный браузер открывает веб-каталог: марка → модель → узел автомобиля → тип детали → карточка. Все 21 998 позиций из текущей CSV-выгрузки доступны в общем поиске. Интерфейс адаптирован для телефона и компьютера; корзина хранится в браузере, список можно скопировать или открыть как черновик обращения к менеджеру в Telegram. Заказ и оплата выполняются после подтверждения менеджером; на сайте они автоматически не создаются.

## Запуск

```sh
npm ci
npm run dev
```

`predev` и `prebuild` создают `public/web-catalog.json` из `server/data/chery-catalog.csv`. Этот файл генерируется, в Git не хранится. Для обновления резервного каталога замените CSV и пересоберите сайт.

`npm run build` собирает и веб-каталог, и прежний Mini App. Telegram launch-параметры или нативный bridge выбирают Mini App. Для разработки Mini App в обычном браузере используйте `/?miniapp=1`; `/?web=1` принудительно открывает веб-каталог.

## Данные и ограничения подбора

- Веб-каталог читает `GET /api/web/catalog`, `GET /api/web/products` и `GET /api/web/products/:code` с сервера из `VITE_API_BASE_URL`. Это открытые **read-only** маршруты, ограниченные общим rate limit сервера. Учётные записи, серверная корзина, заказы и административный API сохраняют прежнюю Telegram-авторизацию.
- Сервер выбирает только активные товары и поля каталога; кэш обновляется раз в минуту. Миграция БД не требуется.
- Если метаданные недоступны при первом открытии, используется резервная выгрузка из репозитория. В интерфейсе явно показаны источник и дата файла; её цены и остатки справочные. Резервная цена рассчитана с текущей стандартной наценкой 14%; она никогда не используется для автоматического оформления заказа. При недоступности уже подключённого живого каталога показывается ошибка, а не незаметная подмена старой ценой.
- В текущей выгрузке в названиях найдены EXEED, CHERY, OMODA, JAECOO, TANK и TENET. У 21 352 позиций марка в описании не определена: они доступны в общем каталоге, но намеренно не приписываются к случайной марке.
- Схемы являются навигационными иллюстрациями. Названия марок, моделей и разделов извлекаются из текста; это не база подтверждённой применяемости. Точный EPC-подбор по позиции на заводском чертеже потребует лицензированной базы схем и связи `VIN / модификация → схема → позиция → OEM-артикул`.
- Текстовая классификация и фильтры общие для сервера и резервной выгрузки: `server/src/catalog/web-taxonomy.ts`. Её использует также frontend, поэтому в этот файл нельзя добавлять серверные зависимости или секреты.

## Развёртывание

1. Установите зависимости и соберите обновлённый backend (`cd server && npm ci && npm run prisma:generate && npm run build`), затем перезапустите его штатным способом. Само размещение frontend сервер не обновляет.
2. При ограниченном `CORS_ORIGIN` добавьте origin веб-версии к существующим разрешённым адресам.
3. Задайте `VITE_API_BASE_URL=https://<backend>/api` при сборке frontend. На общем домене можно указать `/api` и проксировать его на backend.
4. Выполните `npm ci && npm run build` и разместите `dist/`. API и весь HTML должны обслуживаться по HTTPS. Для текущего Mini App сохраните адрес запуска в Telegram; для принудительного режима добавьте `?miniapp=1` до `#/...`.

Private Sites-публикация для просмотра описана в `.openai/hosting.json`. Она содержит статический frontend и резервный каталог; PostgreSQL/NestJS продолжают работать на существующем сервере. Новые маршруты начнут отвечать после развёртывания backend из этой ветки.

## Проверки

```sh
npm run build
npm run test:web
npm run test:bundle
cd server
npm run prisma:generate
npm run test:web
```

Unit-проверки охватывают классификацию без выдуманной применяемости, поиск с перестановкой слов и нормализацией артикула, комбинации фильтров, остатки/партии, пагинацию, выбор режима Telegram/браузер и полноту выгрузки. HTTP-проверки запускают настоящий Nest-контроллер с тестовым источником вместо БД: анонимный доступ, фильтрация, валидация, 404 и кэш.

В этой среде не предоставлен инструмент управления браузером, поэтому визуальная и интерактивная проверка в браузере не выполнялась.

Регрессионная проверка `test:bundle` выполняет собранные production-модули в VM с DOM jsdom: завершение запуска, загрузка каталога, выбор узла и типа детали, добавление в корзину и открытие корзины. Она воспроизводит исправленный цикл импортов с top-level await; браузерный движок в этой проверке не используется.
