# Оформление заказа на сайте

Корзина создаёт гостевой заказ W с отдельным ключом доступа. Покупатель видит состав, актуальную цену и статус в «Моих заказах» в браузере оформления. Чтобы получать статусы и трек в боте, покупатель нажимает «Получать статус в Telegram» и запускает бота по одноразовой ссылке. Оператор получает номер заказа через существующие ORDER_NOTIFY_CHAT_IDS. Очередь склада открывается на https://exeedbot.ru/?warehouse=1 по существующему ADMIN_API_TOKEN.

При выборе подбора менеджер подтверждает VIN. Покупатель, который уже проверил все артикулы, может сразу получить расчёт самовывоза. Сервер сверяет запас, кратность и цену у поставщика при оформлении и перед созданием платежа. При изменении цены он показывает новую сумму на подтверждение. Остаток у поставщика не резервируется его API этой операцией.

## Подключение ЮKassa

1. Оформите договор на ИП или организацию, укажите адрес магазина, подключите карты и СБП. Создайте тестовый магазин. [Подключение](https://yookassa.ru/internet-ekvayring-dlya-saytov/) · [тестирование](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).
2. В серверном файле /opt/tg-miniapp/shared/backend.env задайте YOOKASSA_SHOP_ID, YOOKASSA_SECRET_KEY, YOOKASSA_MODE=test и WEB_STORE_ORIGIN с адресом тестовой витрины. Ключ берётся в разделе «Интеграция → Ключи API». Используйте отдельный тестовый экземпляр со своей базой. На боевом сайте установите live и ключ боевого магазина после приёмки.
3. Если касса получает позиции через ЮKassa, задайте YOOKASSA_RECEIPTS=provider и подтверждённый бухгалтером YOOKASSA_VAT_CODE. Образец интеграции применяет один код НДС к товару и доставке, передаёт телефон и позиции для чека предоплаты. Зачёт предоплаты при передаче товара, возвраты и смешанные налоговые ставки согласуйте с вашей кассой до включения боевых платежей. Вариант external предназначен для магазина с уже работающей отдельной фискализацией.
4. В настройках HTTP-уведомлений укажите https://exeedbot.ru/api/web/checkout/yookassa и события payment.succeeded и payment.canceled. Для тестового магазина укажите хост тестовой витрины. Сервер запрашивает платёж по API и сверяет сумму, валюту, режим и номер попытки. Секреты хранятся только на сервере. Перезапустите процесс tg-miniapp-backend после настройки окружения.
5. На отдельном тестовом экземпляре пройдите оплату, отмену, возврат в заказ и получение тестового чека. Проверьте, что повторный запрос сохраняет один платёж. Затем переключите режим и уведомления на боевой магазин.

## СДЭК и выдача

Укажите данные своего договора CDEK_CLIENT_ID и CDEK_CLIENT_SECRET, CDEK_MOCKED=false, город отправки CDEK_FROM_CITY_CODE и код реального пункта приёма CDEK_SHIPMENT_POINT. Тариф 136 используется для посылки между пунктами. Для тестовой ЮKassa нужен тестовый хост СДЭК https://api.edu.cdek.ru и учётные данные тестового договора.

Склад вводит вес места в граммах, длину, ширину и высоту в сантиметрах, массу единицы каждой позиции в граммах. Для повторяющейся упакованной позиции можно настроить WEB_PACKAGES_JSON. Пример формата с вымышленным кодом:

```json
{"EXAMPLE:2":{"weight":1250,"length":25,"width":20,"height":10,"itemGrams":[500]}}
```

После оплаты склад нажимает «Упакован». Сервер создаёт отправление, сверяет его статус и трек, предоставляет PDF этикетки. Для самовывоза склад отмечает готовность и факт выдачи. Состояние и трек доступны на сайте, подписчикам приходит сообщение в боте. При обрыве связи после отправки сервер проверяет заявку по номеру EXEED-W и не регистрирует вторую посылку. Если СДЭК окончательно отклонил заявку, сверьте её с кабинетом перевозчика. Это также требуется после неоднозначного запроса к банку за пределами срока действия ключа идемпотентности.
