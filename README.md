# tg-miniapp — заказ автозапчастей через Telegram Mini App

Telegram Mini App для поиска и заказа автозапчастей по артикулу: корзина, самовывоз/доставка (СДЭК, Яндекс.Доставка), оплата по QR-ссылке или безналично для юрлиц. Бот зарегистрирован в BotFather; единственная его серверная логика — минимальный webhook-обработчик `/start` в этом же backend (`server/src/bot`), который отвечает кнопкой запуска miniapp. Вся торговая логика — внутри miniapp и обслуживающего её backend.

## Стек и структура репозитория

Репозиторий состоит из двух частей:

```
.
├── src/            # Telegram Mini App — React 18 + TypeScript + Vite
│                    # (@telegram-apps/sdk-react, @telegram-apps/telegram-ui)
├── server/         # Backend — NestJS + PostgreSQL + Prisma
└── docker-compose.yml   # Postgres для локальной разработки
```

Frontend — статический SPA, деплоится отдельно (сейчас на GitHub Pages) и обращается к backend по HTTP через `VITE_API_BASE_URL`. Backend — отдельный деплоящийся Node-процесс со своей базой данных.

## Функциональность

- **Бот `/start`**: webhook-обработчик (`server/src/bot`) отвечает сообщением с кнопкой `web_app`, открывающей miniapp — не требует захода в BotFather, регистрируется один раз через `setWebhook` (см. [DEPLOYMENT-VPS.md](DEPLOYMENT-VPS.md)).
- **Онбординг + авторизация**: первый визит (`/`, нет сохранённого телефона) показывает `WelcomePage` — что за магазин, какие бренды, кнопка «Поделиться номером»; после этого сразу переход в каталог. Возвращающийся пользователь попадает в каталог напрямую. Сессия проверяется через Telegram `initData` (HMAC-подпись), номер телефона запрашивается нативным Telegram API (`requestContact`), без участия бота.
- **Каталог**: поиск товаров по артикулу/названию с постраничной подгрузкой («Показать ещё» — фронт не ограничен первой страницей результатов). Наполняется через admin API (`POST /api/admin/products`) или CSV-импорт (`npm run import:catalog`); сейчас в базе — реальный прайс-лист CHERY (~22 тыс. позиций), импортированный из выгрузки поставщика.
- **Живая цена от поставщика (Avtoliga Parts)**: каталожная цена в БД — индикативная (обновляется при импорте/после заказов). Перед фактическим оформлением заказа backend всегда переспрашивает актуальную цену и остаток у [avtoliga-parts.ru](https://avtoliga-parts.ru) по каждому товару в корзине, берёт самый дешёвый склад, где есть нужное количество, накидывает наценку (`AVTOLIGA_MARKUP_PERCENT`, сейчас 14%) и только эту цену фиксирует в заказе. Если поставщик недоступен — заказ **не оформляется** (503), чтобы не продать ниже себестоимости на устаревших данных. Если живая цена, остаток или кратность расходятся с тем, что клиент видел на экране оформления, заказ тоже не оформляется (409): корзина приводится к актуальным данным, клиент видит, что изменилось, и подтверждает заново — сумму, которую он не видел, списать нельзя. Повторное нажатие «Оформить заказ» второй заказ не создаёт. См. `server/src/avtoliga`, `server/src/orders`.
- **Корзина**: хранится на сервере (переживает закрытие приложения), лимит 10 шт. на одну позицию и не больше остатка. Около 3% позиций поставщик продаёт только партиями (свечи по 20, фильтры по 20–30): цена за штуку, но количество — только кратно партии, а лимит позиции для них — одна партия (`server/src/cart/line-quantity.ts`, кратность берётся из колонки «Минимальная партия» прайса и `InPackage` API); из строки корзины можно открыть карточку товара (артикул, количество в корзине, цена) и вернуться назад — обратно в корзину.
- **Оформление заказа**:
  - способ получения — самовывоз (2 фиксированных адреса в Москве) или доставка (СДЭК / Яндекс.Доставка): сначала выбор города (поиск через СДЭК `/v2/location/cities`), затем ПВЗ в этом городе с поиском по любым словам адреса в любом порядке и реальным сроком доставки (калькуляторы СДЭК и Яндекса) — выбор сразу переводит на следующий шаг. Есть быстрый повтор ПВЗ из последнего заказа. Весогабариты не считаются;
  - способ оплаты — QR-ссылка (генерируется вручную оператором) или безналичная оплата для юрлиц (свободный текст реквизитов организации);
  - оба шага предзаполняются из настроек профиля (см. ниже), если пользователь их сохранил;
  - обязательное согласие с политикой невозврата.
- **Профиль**: помимо телефона — настройки по умолчанию (способ получения, перевозчик, способ оплаты), подставляются при оформлении следующего заказа.
- **Заказы**: после оформления заказ виден в истории пользователя и в admin API (`GET /api/admin/orders`); опционально уходит вебхуком во внешнюю систему обработки (`EXTERNAL_ORDER_WEBHOOK_URL`).
- **Работа оператора в боте**: уведомление о каждом новом заказе, `/queue` — очередь, `/pay <номер> <ссылка>` — выставить оплату (клиенту приходит сообщение с кнопкой «Оплатить»), `/paid <номер>` — отметить оплату. Команды только для `ORDER_NOTIFY_CHAT_IDS`.
- **Автообновление прайса**: прайс поставщика приходит Excel-файлом на почту несколько раз в день; backend читает ящик по IMAP (только чтение), применяет цены с наценкой и остатки, скрывает выбывшие позиции, с предохранителем от битых файлов и отчётом в Telegram (`server/src/price-sync`, см. [DEPLOYMENT-VPS.md](DEPLOYMENT-VPS.md) §12). Вручную — `npm run import:price -- <файл.xls>`.
- **Бэкапы**: каждую ночь дамп базы приходит владельцу в Telegram (`server/deploy/backup/`, см. [DEPLOYMENT-VPS.md](DEPLOYMENT-VPS.md) §11).
- **Защита от автоматизации**: без визуальной капчи (не вписывается в Mini App WebView) — базовый rate-limiting (`@nestjs/throttler`) поверх обязательной HMAC-проверки `initData`, которая и так требует настоящую Telegram-сессию.

Подробное описание API, схемы БД и архитектурных решений — в `server/src` (модули `auth`, `catalog`, `cart`, `delivery`, `orders`, `avtoliga`).

## Быстрый старт (локальная разработка)

### 1. Backend

```bash
cd server
npm install
cp .env.example .env        # заполнить при необходимости (по умолчанию подходит для локальной разработки)
docker compose -f ../docker-compose.yml up -d   # поднимает Postgres на порту 5433
npx prisma migrate dev      # применить миграции
npx prisma db seed          # наполнить тестовыми товарами
npm run start:dev           # backend на http://localhost:3000/api
```

В `server/.env` для локальной разработки без реального Telegram-клиента важны два флага:
- `ALLOW_UNSAFE_INIT_DATA=true` — позволяет авторизоваться с замоканной initData из `src/mockEnv.ts`, минуя проверку подписи бота.
- `CDEK_MOCKED=true` / `YANDEX_MOCKED=true` — раздельные флаги на каждого перевозчика (фиктивный список ПВЗ вместо реального API, удобно без боевых кредов). В проде оба переведены на боевые API. Перевозчик, оставшийся в мок-режиме, в проде вообще не предлагается пользователю (`GET /api/delivery/carriers`) — чтобы клиент не выбрал несуществующий ПВЗ.

**Оба флага обязательно выключить (`false`) перед продакшн-деплоем** — см. [DEPLOYMENT.md](DEPLOYMENT.md).

Отдельно: `AVTOLIGA_API_TOKEN` и `AVTOLIGA_ADDRESS_ID` — без них `POST /api/orders` всегда будет падать с `503` (живая проверка цены — обязательный шаг оформления, заглушки/мок-режима для неё нет). Токен выдаётся в личном кабинете avtoliga-parts.ru, `AddressId` — через `POST /get/addresses/` с этим токеном.

### 2. Frontend

```bash
npm install
echo "VITE_API_BASE_URL=http://localhost:3000/api" > .env.local
npm run dev          # http://localhost:5173/tg-miniapp/
```

Как и в оригинальном шаблоне, `src/mockEnv.ts` подменяет Telegram-окружение при разработке вне Telegram-клиента — приложение можно открыть в обычном браузере.

## Скрипты

**Корень репозитория (frontend):**
- `npm run dev` / `npm run dev:https` — режим разработки
- `npm run build` — сборка (`tsc --noEmit && vite build`)
- `npm run lint` — ESLint (примечание: в исходном шаблоне не настроена типизация для `recommendedTypeChecked` в `eslint.config.js` — известная проблема конфигурации, не связанная с бизнес-логикой)
- `npm run deploy` — ручной деплой на GitHub Pages

**`server/` (backend):**
- `npm run start:dev` — режим разработки с watch
- `npm run build` / `npm run start:prod` — прод-сборка и запуск
- `npm run prisma:migrate` / `npm run prisma:seed` — миграции и тестовые данные
- `npm run import:catalog -- <path.csv>` — импорт каталога товаров из CSV (upsert по артикулу)
- `npm run import:price -- <price.xls> [--force]` — применить прайс поставщика (.xls/.xlsx) как полный снимок каталога
- `npm run test` — юнит-тесты (Jest)

## TON Connect

В шаблоне остался нетронутым интеграционный код TON Connect (`@tonconnect/ui-react`, страница `/ton-connect`, `public/tonconnect-manifest.json`) — он не относится к функциональности заказа запчастей и не используется бизнес-логикой. Можно удалить, если не планируется использовать TON-кошельки, либо оставить как есть.
